Why nothing traded

root cause first

First failing precondition: Broker credentials present. Everything below it is downstream of that, so fixing lower items alone changes nothing.

  1. Every secret and variable reaches the engine empty
    The Actions env block echoes each one with nothing after the colon. ENABLE_TRADING being empty is the one that looks harmless and is not: run_scan._env_bool falls back to True, so the engine believes trading is enabled while having no way to trade.

  2. No price source can answer, so price is always None
    Both fetchers short-circuit on the missing key before any network call. Executed directly against engine.py from origin/main:
    fetch_alpaca_price('AEHR','','')  -> (None, 'No Keys')
fetch_polygon_price('AEHR','')    -> (None, 'No Key')
  3. The indicator fallback is rate-limited on every ticker
    With no Alpaca keys, fetch_indicators_hybrid falls through to yfinance and is throttled. The 43 errors per run match engine.DEFAULT_TICKERS exactly -- 43 tickers, 43 refusals -- which also confirms WATCHLIST being empty means the built-in list is what runs.

len(engine.DEFAULT_TICKERS) == 43
  4. decide() therefore returns HOLD unconditionally
    The function's first guard is `if price and rsi > 0`. price is None, so the guard never opens and no branch is reachable. This is not the strategy being cautious -- it is the strategy never being consulted.
    decide(None, 0.0, 0.0, 0.0)      -> ('HOLD', 0.0)   # observed every run
decide(100.0, 95.0, 55.0, 0.40) -> ('BUY', 0.84)    # same code, healthy inputs
  5. The trial phase is pinned to DRY_RUN permanently
    Without TRIAL_GITHUB_TOKEN, get_trial_start_date() returns None, and get_trial_phase(None) returns DRY_RUN with no day counter. The 60-day clock has never started, which is why the log reads 'day None'. Day 31 -- when PAPER would begin -- is unreachable, not merely distant.

get_trial_phase(None) -> ('DRY_RUN', None)
  6. Opening a position is impossible even if a signal fired
    Two independent gates both fail: no broker credentials, and the wrong phase. Either one alone is sufficient to block every order.
    trading_base_ready = enable_trading AND alpaca_id AND alpaca_secret  -> False
can_open_new       = trading_base_ready AND phase == 'PAPER'         -> False
can_close          = trading_base_ready AND phase in (PAPER,REVIEW) -> False
  7. And nothing was recorded, so there is no history to analyse
    Each run reports zero new log entries, and the branch the log would live on does not exist. 440 runs of state were computed and discarded. This report had to be reconstructed from Actions logs because the engine's own audit trail is empty.

What to fix, in order

to start week 1 for real
  1. Make a dead run fail instead of reporting success
    This is the real finding: 440 consecutive green runs concealed a total outage. Add an assertion at the end of run_scan.py -- if zero tickers produced a usable price, exit non-zero. A red workflow would have surfaced this on day one instead of week eleven. Do this first, because it is what protects every fix below.
  2. Set ALPACA_ID and ALPACA_SECRET to the PAPER account keys
    Repo Settings -> Secrets and variables -> Actions. Paper keys only; live keys return 401 against the hardcoded paper endpoint, which is the intended safety behaviour. This unblocks both the price source and trading_base_ready.
  3. Set TRIAL_LOG_TOKEN so the trial clock can start
    A fine-grained PAT scoped to this repo with Contents: Read and write. The engine reads it as TRIAL_GITHUB_TOKEN. On the first run with it set, get_trial_start_date() bootstraps today's date, creates the bot-trial-log branch, and the 60-day clock begins -- 30 days DRY_RUN, then PAPER. Until this exists, no amount of other configuration starts paper trading.
  4. Give the indicator path a data source that is not rate-limited
    Set POLYGON_KEY and TIINGO_KEY, or have fetch_indicators_hybrid use the Alpaca bars endpoint once keys exist. 43 HTTP 429s per run means the free fallback is exhausted before it returns a single bar, so even with broker keys the RSI/SMA path needs its own fix.
  5. Replace the */15 cron with a schedule GitHub will actually honour
    The requested 96 runs/day is delivering about 3.6. Pick an explicit market-hours schedule (e.g. every 30 minutes, 13:30-20:00 UTC, weekdays) so the cadence is predictable and the engine is not firing at 01:50 UTC when the market is shut.
  6. Set WATCHLIST, NOTIONAL_PER_TRADE and MAX_POSITIONS explicitly
    All three are currently empty and running on code defaults (DEFAULT_TICKERS, $500, 8 positions). Defaults are fine as behaviour but invisible as configuration -- set them so the deployed values are stated rather than inferred.
